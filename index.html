-- SYNTHETIC EXAMPLE · no internal tables or data WITH fab_ranked AS ( SELECT f.lot_id, f.wafer_id, f.eqp_id, f.chamber_id, f.product_id, f.step_id, f.route_id, f.recipe_id, f.process_time, ROW_NUMBER() OVER ( PARTITION BY f.lot_id, f.wafer_id, f.step_id ORDER BY f.process_time DESC, f.event_id DESC ) AS fab_rn FROM demo_fab_history AS f INNER JOIN demo_product_catalog AS p ON p.product_id = f.product_id INNER JOIN demo_step_catalog AS s ON s.step_id = f.step_id WHERE p.product_code = 'V9' AND s.process_group = 'MAIN' AND s.step_seq = '09' AND f.process_time >= CURRENT_DATE - INTERVAL '150 days' AND f.record_status = 'VALID' ), yield_ranked AS ( SELECT y.lot_id, y.wafer_id, y.test_time, y.good_die_count, y.total_die_count, ROW_NUMBER() OVER ( PARTITION BY y.lot_id, y.wafer_id ORDER BY y.test_time DESC, y.test_id DESC ) AS yield_rn FROM demo_yield_measurement AS y WHERE y.test_time >= CURRENT_DATE - INTERVAL '100 days' AND y.total_die_count > 0 AND y.test_status = 'COMPLETE' ), fab_latest AS ( SELECT * FROM fab_ranked WHERE fab_rn = 1 ), yield_latest AS ( SELECT * FROM yield_ranked WHERE yield_rn = 1 ), joined_data AS ( SELECT f.lot_id, f.wafer_id, eq.eqp_name, ch.chamber_name, rt.route_name, rc.recipe_name, f.process_time, y.test_time, 100.0 * y.good_die_count / NULLIF(y.total_die_count, 0) AS yield_pct, lm.lot_type, wm.wafer_size FROM fab_latest AS f INNER JOIN yield_latest AS y ON y.lot_id = f.lot_id AND y.wafer_id = f.wafer_id AND y.test_time >= f.process_time INNER JOIN demo_equipment_catalog AS eq ON eq.eqp_id = f.eqp_id LEFT JOIN demo_chamber_catalog AS ch ON ch.eqp_id = f.eqp_id AND ch.chamber_id = f.chamber_id LEFT JOIN demo_route_catalog AS rt ON rt.route_id = f.route_id LEFT JOIN demo_recipe_catalog AS rc ON rc.recipe_id = f.recipe_id INNER JOIN demo_lot_master AS lm ON lm.lot_id = f.lot_id INNER JOIN demo_wafer_master AS wm ON wm.lot_id = f.lot_id AND wm.wafer_id = f.wafer_id WHERE lm.lot_type = 'PRODUCTION' AND wm.wafer_status <> 'SCRAP' ) SELECT eqp_name, chamber_name, recipe_name, COUNT(*) AS wafer_count, ROUND(AVG(yield_pct), 4) AS mean_yield, ROUND(STDDEV_SAMP(yield_pct), 4) AS yield_std, MIN(test_time) AS first_test, MAX(test_time) AS last_test FROM joined_data GROUP BY eqp_name, chamber_name, recipe_name HAVING COUNT(*) >= 3 ORDER BY mean_yield, eqp_name, chamber_name;

소개

안녕하세요. V5P 소속 이유정입니다. 오늘은 Flash YE의 통합 데이터 분석 툴인 데이터톡을 소개해드리겠습니다.

데이터톡은 현재 YE팀에서 구축 중인 전용 DB인 Flake DB를 바탕으로, 자연어로 데이터를 조회하고 시각화와 분석까지 연결하는 프로젝트입니다.

소속과 이름을 소개하고, 자연어 조회·시각화·분석의 연결을 강조한 뒤 2장으로 이동합니다.

발표자

전용 DB 도입 배경

저는 그동안 데이터레이크에서 주로 데이터를 추출해왔습니다. 그런데 전사 공용 툴이다 보니, 조회가 몰리는 시간에는 필요한 데이터를 제때 꺼내 쓰기가 어려웠습니다.

해결 방법을 찾던 중에 PA팀에서 사용하고 있는 Flake DB를 알게 됐습니다. 데이터를 많이 다루는 YE팀에도 이런 기반이 필요하다고 생각했고, 제가 작년 팀 내 AX 아이디어 경진대회에서 전용 DB 도입을 제안했습니다.

그 제안이 실제 투자로 이어져서, 현재 Flash YE 전용 Flake DB가 구축 중입니다.

앞으로 생산량이 늘어나면 데이터는 그보다 더 많이 쌓이게 되고, 그만큼 제가 겪었던 이런 불편함도 더 커질 수밖에 없는데요. 이번 전용 DB 구축은 기존 파일 시스템 기반 데이터레이크의 한계를 보완하고, 늘어나는 데이터를 안정적으로 활용하기 위한 기반을 마련하는 과정이라고 생각합니다.

조회 지연 경험 → 직접 도입 제안 → 실제 투자·구축 중인 전용 DB 순서로 설명합니다.

발표자

이번 AX 프로젝트에서 개선하고 싶은 것

이번 AX 프로젝트를 통해 제가 더 개선하고 싶은 것은, 바로 그 DB의 활용성입니다.

화면에 보이는 게 데이터를 추출하기 위해 사용자가 작성해야 하는 SQL 쿼리문입니다. 딱 보셔도 굉장히 길고 복잡한데요. 한두 번의 교육만으로 이런 쿼리를 자유롭게 활용해서 원하는 데이터를 추출하기는 쉽지 않습니다.

PA팀에서는 상황별로 SQL문을 정리해두고, 사용자가 필요한 부분을 수정해서 사용하는 것으로 알고 있습니다.

그런데 이 방식도 SQL에 대한 이해가 어느 정도 필요합니다. DB에서 할 수 있는 일은 많아도, 실제 사용자가 활용하는 범위는 제한적일 수 있습니다.

그래서 저는 엔지니어가 필요한 데이터를 좀 더 쉽게 활용할 수 있도록 만들고 싶었습니다.

화면의 SQL을 짚고, 교육·템플릿 수정만으로는 활용에 한계가 있다는 점을 설명합니다.

발표자

DataTalk의 핵심과 시연 안내

데이터톡의 핵심은 엔지니어가 평소에 사용하는 말로 필요한 데이터를 요청하고 추출하는 것입니다.

사용자가 필요한 데이터와 조건을 말하면, AI가 빠진 조건을 물어봅니다. 대화를 통해 조건이 맞춰지면, 그에 맞는 데이터를 추출하는 방식입니다.

여기에 시각화와 분석 기능을 더해서, 간단한 작업은 데이터를 PC로 내려받지 않고도 앱 안에서 바로 확인하고 분석할 수 있는 통합 데이터 분석 툴로 발전시키고자 합니다.

이제 시연 화면을 한번 보시겠습니다. 시연은 외부 AI를 활용해 제작했고, 사내 정보와 실제 데이터는 들어있지 않습니다. 모두 가상값으로 구성한 화면이라는 점을 참고해주시면 좋겠습니다.

자연어 요청 → 부족한 조건 확인 → 추출·분석의 흐름을 소개합니다. 가상값 시연임을 안내하고 5장으로 이동합니다.

팹 이력은 150일, 수율 데이터는 100일로 답합니다. 데이터마다 다른 조회 기간도 대화로 전달할 수 있습니다.

조건이 정해지면 두 데이터를 조회하고, 로트와 웨이퍼를 기준으로 결합합니다. 오른쪽에는 설비별 수율을 확인할 수 있는 결과가 나타납니다.

AI 시연 · 시각화·ANOVA로 확장

이어서 처음 요청한 아노바 분석으로 넘어갑니다. 이미 연결된 분석 도구에 설비는 비교 그룹으로, 수율은 측정값으로 전달합니다.

분석 결과에서 설비 그룹 간 평균 수율 차이를 확인합니다. 다만, 차이가 있다는 결과만으로 설비가 원인이라고 단정하지는 않습니다.

평균과 함께 상자그림으로 분포를 보면, 그룹별 데이터의 퍼짐과 이상값도 살펴볼 수 있습니다.

그룹별 결과표도 같은 작업공간에서 확인하고, 필요한 결과만 저장할 수 있습니다. 이렇게 조회에서 데이터 결합과 분석까지 하나의 흐름으로 이어집니다.

문단 순서대로 9·10·11·12장에 맞춥니다. 음성 생성 시 문단 사이 약 1초 쉬기. 12장은 결과표에서 전체 UI로 축소하고, 13장부터 발표자가 이어갑니다.
